# สเปก Dashboard ผลโฆษณา

ใช้ MODE 5 / บทที่ 4; นี่คือกติกาการแสดงผลของ repo ไม่ใช่ข้อกำหนดหน้าจอ LINE
แหล่งนิยาม: [report-metrics.md](report-metrics.md) [M]; การเลือก KPI: [kpi-benchmarks.md](kpi-benchmarks.md#objective-benchmarks) [K]
ขอบเขต MCP/Artifact: [กฎหลัก](../CLAUDE_PROJECT_PROMPT.md#tools-ที่มีและใช้เมื่อไหร่) [C] ตาม contract ที่เจ้าของอนุมัติ 2026-10-18
ข้อกำหนด layout/การเทียบด้านล่างเป็น **กติกาออกแบบของเอกสารนี้** ไม่ใช่ benchmark หรือฟีเจอร์ API

## ข้อมูลเข้า

- เริ่มจากคำขอในแชท AI อ่านบัญชีผ่าน MCP เอง; ถามทีละเรื่องเฉพาะสิ่งที่ยังไม่ทราบ ไม่ขอไฟล์รายงาน [C]
- อ่าน `list_campaigns(status=None, fetch_all=True)` เพื่อผูก objective/name; อ่าน `list_ads(adset_id=None, campaign_id=None, status=None, fetch_all=True)` เมื่อขาด parent/name ไม่ตัดประวัติเพราะสถานะปัจจุบัน PAUSED/REMOVED [C; กติกาจัดข้อมูล]
- ดึง `get_report(level="CAMPAIGN", start_date=..., end_date=..., fetch_all=True, by_day=True)` สำหรับ trend และ `get_report(level="AD", start_date=..., end_date=..., fetch_all=True, by_day=False)` สำหรับตาราง ad; อย่าบวกสองระดับเป็นยอดเดียว [C][M]
- ตรวจ paging, UTC, duplicate, หน่วย, currency และ missing ก่อนแสดงทุกครั้ง; แบ่งคำขอรายวันเกิน 93 วันเป็นช่วงไม่ซ้อน [M]
- ถ้ามีประวัติ CSV ที่เข้าถึงได้อยู่แล้ว AI อ่านเสริมได้เมื่อวัน/หน่วยตรงและไม่ซ้ำ; ไม่มีให้ใช้ MCP ต่อ ไม่ให้ผู้อ่านเตรียมไฟล์และไม่เรียก `sync_ad_daily_csv` ในบทนี้ [C; กติกาจัดข้อมูล]

## KPI tiles

ทุก objective แสดง “ใช้จ่าย” และ “การแสดงผล” ก่อน แล้วแยกชุด KPI ตามตาราง; ไม่รวม results คนละชนิดเป็นก้อนเดียว [M][K; กติกาออกแบบ]

| Objective | ป้าย KPI ภาษาไทย | ข้อมูลที่ต้องมี |
|---|---|---|
| GAIN_FRIENDS | เพื่อนใหม่โดยประมาณ, ต้นทุนต่อเพื่อน (CPF), อัตราคลิก | click; CPF ตาม convention repo ไม่ใช้ cv [M][K] |
| VISIT_MY_WEBSITE | คลิก, ต้นทุนต่อคลิก (CPC), อัตราคลิก (CTR) | click, imp, spend [M][K] |
| WEBSITE_CONVERSION | คอนเวอร์ชัน, ต้นทุนต่อคอนเวอร์ชัน (CPA), อัตราคอนเวอร์ชัน (CVR) | cv, click, spend; เพิ่ม ROAS เฉพาะมีรายได้ยืนยัน [M][K] |
| REACH | การเข้าถึง, ต้นทุนต่อพันครั้ง (CPM), ความถี่ | Reach/Frequency จริง; ไม่มีให้ “ไม่มีข้อมูล” ไม่แทนด้วย imp [M][K] |
| APP_INSTALL | ติดตั้งแอป, ต้นทุนต่อติดตั้ง (CPI) | install metric จริง; ไม่ใช้ click แทน [M][K] |
| VIDEO_VIEW | ดูวิดีโอ, ต้นทุนต่อการดู (CPV), อัตราดูจบ | นิยาม view/completion ของ field จริง [M][K] |

แสดง currency จริง, % และหน่วยครั้ง/คนให้ตรง metric; ถ้ายังไม่ยืนยันเงินให้ติด “หน่วยเงินยังไม่ยืนยัน” ไม่เติมสัญลักษณ์บาทเอง [M]
Benchmark เป็นบริบทตาม objective/อุตสาหกรรมใน [K] ไม่ใช่สีผ่าน/ตกตายตัว; เกณฑ์สีหรือ volume ต้องระบุว่า heuristic และเจ้าของปรับได้ [กติกาออกแบบ]

## Layout และกราฟ

| ส่วน | แสดงอะไร | กติกาออกแบบ |
|---|---|---|
| หัวหน้า | “ผลโฆษณา”, ช่วง UTC, “ดึงข้อมูลเมื่อ”, source, ความครบ | แสดง filter/objective/currency ชัดเจน [M] |
| KPI tiles | ยอดช่วงที่เลือกและ KPI แยก objective | ratios จากผลรวม ไม่เฉลี่ยรายแถว [M] |
| กราฟเส้นรายวัน | ใช้จ่ายและผลลัพธ์แยก objective | ใช้คนละกราฟหรือแกนที่ระบุหน่วย; ห้ามเส้นเงินกับจำนวนบนแกนเดียวโดยไม่อธิบาย |
| ตารางแคมเปญ | ชื่อ/ID, objective, ใช้จ่าย, results, cost per result, CTR | เรียง spend มาก→น้อยเป็นค่าเริ่มต้น |
| ตารางโฆษณา | ชื่อ/ID, campaign, ใช้จ่าย, KPI ตาม objective | เรียง spend มาก→น้อย; ไม่มีภาพจริงไม่แต่ง preview |
| ข้อจำกัด | วัน/metric ที่ขาด, paging, หน่วยไม่ยืนยัน, sample ต่ำ | ให้เห็นใกล้ KPI ที่ได้รับผล ไม่ซ่อนไว้ท้ายอย่างเดียว [M] |

กราฟต้องใช้แถวรายวันจริง ห้ามแบ่งยอดทั้งช่วงเฉลี่ยเป็นแต่ละวัน; unknown ให้เส้นขาด ไม่ลากเส้นเชื่อมเหมือนมีข้อมูล [M; กติกาออกแบบ]
Reach ไม่บวกข้ามวัน/แคมเปญให้เป็น unique reach ทั้งบัญชี; แสดงเฉพาะขอบเขตที่ต้นทางคืนมา [M]
รายการเท่ากันให้เรียง ID เพื่อให้อ่านเทียบรอบ refresh ได้ง่าย; ตารางแยก objective หรือมี filter ป้องกันการเทียบ CPF กับ CPA [กติกาออกแบบ]

## เทียบช่วงก่อนหน้า (period-over-period)

กติกาวิเคราะห์ของ dashboard นี้ ใช้ร่วมกับ [planning-from-history.md](planning-from-history.md#เทียบให้เป็นธรรม):

1. ใช้ช่วงเต็ม UTC จำนวนวันเท่ากัน ติดกันไม่ซ้อน และชุด filter/objective/currency เดียวกัน; เทียบชนิดผลลัพธ์และ attribution/tracking ที่สอดคล้อง [M]
2. ระบุวันเริ่ม/จบของทั้งสองช่วง; ถ้ามีวันนี้ที่ยังไม่เต็ม ให้แยกจากการเทียบวันเต็ม ไม่แอบเติม 0 [M]
3. จำนวน/เงิน: `การเปลี่ยนแปลง (%) = (ใหม่−เดิม)/เดิม × 100` เมื่อเดิม > 0 และทั้งคู่ครบ; เดิม 0 ให้แสดงผลต่างพร้อม “ฐานเดิมเป็น 0” ไม่แสดง ∞% [สูตรวิเคราะห์]
4. CTR/CVR: คำนวณใหม่จากผลรวมแต่ละช่วง แล้วแสดงผลต่างเป็น **จุดเปอร์เซ็นต์**; ถ้าจะแสดง % เปลี่ยนแปลงต้องแยกป้ายชัด [M; สูตรวิเคราะห์]
5. CPF/CPC/CPA/CPM ลดลงหมายถึงต้นทุนต่อหน่วยลด ไม่ได้แปลว่ายอดขายหรือคุณภาพดีขึ้น; หลีกเลี่ยงสีเขียวโดยไม่ดู objective/volume [M; กติกาตีความ]
6. ถ้าช่วงใด incomplete, หน่วยไม่ยืนยัน หรือ denominator หาย ให้ “ยังเทียบไม่ได้”; sample น้อยติดป้ายตามเกณฑ์ [M] ไม่จัดอันดับผู้ชนะ
7. การเปลี่ยนจากช่วงก่อนบอกความสัมพันธ์ ไม่พิสูจน์ว่า creative/targeting เป็นสาเหตุ; แสดงความต่างของ offer/bid/งบที่ทราบประกอบ [planning-from-history.md](planning-from-history.md)

## Unknown, zero และ refresh

| สถานะ | ป้ายภาษาไทย | วิธีแสดงตาม [M] |
|---|---|---|
| คืนเลขศูนย์จริง | `0` | ใช้เลขศูนย์ได้ |
| ไม่คืน field / null / วันไม่มีแถว | “ไม่มีข้อมูล” | tile เป็น `—`, กราฟเว้นช่อง |
| ตัวหาร 0 | “คำนวณไม่ได้” | ไม่แสดงต้นทุนเป็น 0 |
| paging ไม่ครบ/ไม่ทราบ | “ข้อมูลบางส่วน” | “ยอดที่ดึงได้” ไม่เรียกยอดทั้งบัญชี |
| ไม่มีรายได้ | “ไม่มีข้อมูลรายได้” | ไม่แต่ง ROAS เป็น 0 |

Claude สร้าง **Artifact** เอง ไม่มี dashboard MCP tool; Artifact เป็น snapshot ไม่ใช่ live connection [C]
“รีเฟรช dashboard” = เรียก MCP ใหม่ ตรวจข้อมูลใหม่ และสร้าง/ปรับ Artifact พร้อมเวลาเรียกใหม่; การเปิด Artifact เดิมไม่ใช่ refresh [C; กติกาออกแบบ]
ถ้าสร้าง Artifact ไม่สำเร็จ ให้สรุปตารางในแชทและบอกข้อจำกัด ไม่อ้างว่ามี dashboard แล้ว [กติกาออกแบบ]
บทนี้อ่านอย่างเดียว ไม่สร้าง/แก้/หยุดโฆษณาหรือเขียน CSV; งานตั้งเวลาส่งต่อ [workflows/03-report-schedule.md](../workflows/03-report-schedule.md) ไม่แต่ง scheduler tool [C]
