## MCP/API Verified Advanced Targeting Codes

ใช้ส่วนนี้เป็น local cache ก่อนเรียก `list_advanced_targeting_codes` เพื่อประหยัด API/tool calls และลดการพึ่งพา external lookup ระหว่างสร้าง campaign

Context ที่ verify แล้ว:
- `campaignObjective=GAIN_FRIENDS`
- `country=TH`
- `locale=th`
- Source: LINE Ads API `/codes/advanced-targeting`
- Last verified: 2026-05-13
- Total selectable codes cached: 267

Cache นี้รวม advanced targeting หลายชนิด ไม่ใช่ interest อย่างเดียว:
- `interests` ใช้กับ `interest_codes` / `interest_groups`
- `behaviors` ใช้กับ `behavior_codes`
- `purchaseIntents` ยังถูก cache ไว้เพื่ออ้างอิง แต่ tool ปัจจุบันยังไม่ได้ expose เป็น dedicated parameter

### Business use-case mapping

| Target segment | Recommended narrow groups | Notes |
|---|---|---|
| SME / เจ้าของกิจการทั่วไป | `[["4"]]` | broad business owner proxy |
| เจ้าของโชว์รูม | `[["4"], ["12"]]` | business + automotive |
| พ่อค้าแม่ค้าออนไลน์ | `[["4"], ["31"]]` | business + shopping/ecommerce |
| คลินิกเสริมความงาม | `[["4"], ["1604"]]` | business + beauty |
| ร้านเสื้อผ้าออนไลน์ | `[["4"], ["31"], ["1605"]]` | business + shopping + fashion |
| ร้านอาหาร / F&B owner | `[["4"], ["1607"]]` | business + food |

### Code selection rules

1. หา segment จากตาราง mapping ก่อน
2. ถ้าต้องการ audience แคบ ให้ส่งเป็น `interest_groups`
3. ถ้าต้องการ audience pool แบบกว้าง ให้ส่งเป็น `interest_codes`
4. ถ้าใช้ behavior เช่น กำลังซื้อ ให้ส่งผ่าน `behavior_codes`
5. ถ้า segment ไม่มีใน cache นี้ ค่อยเรียก API เพื่อ refresh

### Narrow targeting payload pattern

ถ้าต้องการ narrow/intersection ให้ใช้ `interest_groups` แทนการรวมทุก code ใน `interest_codes`

```python
interest_groups=[["4"], ["12"]]
```

จะสร้าง payload:

```json
"includeAdvancedTargetings": [
  { "interests": ["4"] },
  { "interests": ["12"] }
]
```

หลีกเลี่ยงกรณีนี้เมื่อต้องการ narrow:

```json
"includeAdvancedTargetings": [
  { "interests": ["4", "12"] }
]
```

เพราะ LINE มีแนวโน้มตีความเป็น audience pool แบบรวม ไม่ใช่ narrow/intersection
