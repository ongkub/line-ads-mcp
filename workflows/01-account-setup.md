## ลำดับการทำงาน (Overview)

```
PHASE 1   → Business Type Check (ขายอะไร?)
PHASE 1.5 → Account Type Check (สมัครในนามใคร?)
PHASE 1.6 → Data Entry Mode (กรอกเองบนเว็บ หรือให้ AI ถามแล้วกรอกให้)
PHASE 2A  → เอกสาร (เฉพาะกลุ่ม B)
PHASE 2B  → Worksheet (แตกตาม Account Type)
PHASE 3   → Browser Automation (กรอกฟอร์ม 4 Steps)
PHASE 4   → Verify + Troubleshoot
PHASE 5   → MCP Handoff (.env + read-only smoke test)
```

> **หลักการสำคัญ:** ต้องรู้ Business Type + Account Type ก่อน ค่อยเตรียม worksheet
> เพราะ Account Type ต่างกัน → ฟิลด์ที่ต้องกรอกต่างกัน

> **MCP boundary:** Account setup/KYC/payment ยังเป็น Browser/UI-only จึงไม่ใช้ MCP สร้างบัญชี แต่หลังได้ Access Key / Secret Key / Ad Account ID แล้วต้อง handoff ไป MCP Layer เพื่อทำ campaign/report/optimize ต่อ

## PHASE 1 — BUSINESS TYPE CHECK

ถามก่อนเสมอ:
> "ธุรกิจหรือสินค้าของคุณเป็นประเภทไหนครับ?"

จัดกลุ่ม (อ้างอิง knowledge/line-ads-guidelines.md):

**กลุ่ม A — สมัครได้ทันที:**
ร้านค้าออนไลน์, บริการทั่วไป, Education, Software/App,
Fashion, Restaurant (อาหารปรุงสำเร็จ), Entertainment, Digital Agency

**กลุ่ม B — ต้องเตรียมเอกสารก่อน:**
อาหาร/เครื่องดื่ม (packaged), อาหารเสริม, เครื่องสำอาง,
ยา, ตัวแทนขายสินค้า, NGO, สถาบันการเงิน

**กลุ่ม C — ห้ามสมัคร:**
บุหรี่, Crypto, อาวุธ, แชร์ลูกโซ่, การพนัน,
เนื้อหาผู้ใหญ่, นมผง/อาหารทารก, ยาเสพติด

ถ้าเป็น **กลุ่ม C:**
> "ขออภัยครับ ประเภทธุรกิจนี้ไม่สามารถลงโฆษณาบน LINE Ads ได้ตามนโยบายของ LINE ครับ"
→ จบ workflow

## PHASE 1.5 — ACCOUNT TYPE CHECK

ถามต่อหลังผ่าน Business Type:

> "สมัครบัญชีในนามไหนครับ?
> [A] **นิติบุคคล** — บริษัท/หจก. ที่จดทะเบียนในไทย (มี Tax ID 13 หลัก)
> [B] **นิติบุคคลต่างประเทศ** — บริษัทต่างชาติที่ไม่ได้จดในไทย
> [C] **ธุรกิจส่วนตัว / บุคคลธรรมดา** — ฟรีแลนซ์, ขายของส่วนตัว, ยังไม่จดบริษัท"

→ Account Type นี้จะกำหนดว่า worksheet ใน PHASE 2B ต้องเก็บข้อมูลอะไรเพิ่ม

**คำเตือนที่ต้องบอก user ก่อนถัดไป:**
> "หลังสมัครเสร็จ มีข้อมูล 4 อย่างที่**เปลี่ยนไม่ได้**หลังกด "สร้าง" คือ:
> หมวดหมู่ธุรกิจ, ประเทศเป้าหมาย, เขตเวลา, สกุลเงิน
> ผมจะ stop ให้ตรวจ Preview ก่อนกด submit ทุกครั้งครับ"

## PHASE 1.6 — DATA ENTRY MODE

ถามหลังรู้ Business Type + Account Type แล้ว ก่อนเริ่มเก็บ worksheet:

> "ตอนกรอกข้อมูลบัญชี อยากทำแบบไหนดีครับ?
>
> 1. กรอกเองบนหน้าเว็บ — ประหยัด token และเร็วกว่า ผมช่วยบอกว่าช่องไหนต้องใส่อะไร
> 2. ให้ผมถามในแชทแล้วกรอกให้ — ง่ายกว่า เหมาะถ้าไม่อยากไล่ดูฟอร์มเอง แต่ใช้ token/เวลามากกว่า
>
> แนะนำ: ถ้าข้อมูลพร้อมและอยากประหยัด เลือก 1 ครับ"

บันทึกเป็น `entry_mode`:
- `SELF_FILL` = user กรอกเองบนเว็บ, Cowork ทำหน้าที่นำทาง + checklist + ตรวจ preview
- `AI_ASSISTED` = Cowork ถามข้อมูลในแชท, สรุปให้ user ยืนยัน, แล้วกรอกฟอร์มให้เป็น batch

ถ้า user ไม่แน่ใจ ให้ default เป็น `SELF_FILL` เพราะประหยัด token กว่า และยังปลอดภัยกว่าเรื่องข้อมูลส่วนตัว

ทั้งสอง mode ยังต้องหยุดให้ user ตรวจ preview ก่อน submit และห้าม Cowork กรอก password/OTP/บัตร

## PHASE 2A — เอกสาร (กลุ่ม B เท่านั้น)

แจ้ง checklist ตามประเภท:

**อาหาร/เครื่องดื่ม (packaged):**
- ใบอนุญาตผลิตอาหาร หรือใบจดทะเบียนอาหาร (อย.)
- ฉลากสินค้าที่ได้รับอนุมัติ
- หนังสือรับรองบริษัท (กรณีนิติบุคคล)

**อาหารเสริม:**
- เลขทะเบียน อย. ของแต่ละผลิตภัณฑ์
- ห้าม claim การรักษาโรค

**เครื่องสำอาง:**
- ใบจดแจ้งเครื่องสำอาง (อย.) ต่อ SKU
- ห้าม claim เกินจริง

**ตัวแทนขายสินค้า:**
- หนังสือแต่งตั้งตัวแทนจากบริษัทแม่
- หนังสือรับรองสิทธิ์การโฆษณา

**NGO:**
- หนังสือจดทะเบียนจาก กรมการปกครอง / กระทรวงแรงงาน

เสนอ 2 ทางเลือก:

## PHASE 2B — WORKSHEET (แตกตาม Account Type)

ใช้เฉพาะเมื่อ `entry_mode = AI_ASSISTED`

ถ้า `entry_mode = SELF_FILL`:
- ไม่ต้องถามข้อมูลทุก field ในแชท
- แสดง checklist สั้นตาม Account Type ให้ user เตรียมไว้
- เปิดเว็บและบอกช่องที่ต้องกรอกทีละ section
- Cowork อ่านหน้าแบบ interactive/DOM เพื่อช่วยตรวจว่าผ่านแต่ละ step หรือยัง

Self-fill checklist แบบสั้น:

```

- ที่อยู่ + รหัสไปรษณีย์, เบอร์โทร, ชื่อ/อีเมลผู้ติดต่อ

- Tax ID/เลขบัตร และข้อมูลบริษัท/บุคคลตามประเภทบัญชี
```

## PHASE 3 — BROWSER AUTOMATION

เริ่มหลังจาก:
- `SELF_FILL`: user เลือกกรอกเอง และเห็น checklist เตรียมข้อมูลแล้ว
- `AI_ASSISTED`: user ยืนยัน Summary จาก PHASE 2B แล้ว

Browser execution:
- อ่าน interactive/DOM ก่อน screenshot ทุกครั้ง
- ใช้ ref/form input เพื่อกรอกหลายช่องใน batch
- screenshot เฉพาะหน้า preview ก่อน submit, error, หรือจุดที่ต้องตรวจภาพจริง
- Low-risk navigation ทำต่อได้หลังบอก user สั้น ๆ; submit/payment ต้องรอ confirm ชัดเจน

ถ้า `entry_mode = SELF_FILL`:
- Cowork เปิด/นำทางไปยังฟอร์ม แล้วให้ user กรอกเอง
- Cowork ไม่ต้องอ่าน/เก็บข้อมูลส่วนตัวในแชท
- หลัง user บอกว่ากรอกเสร็จในแต่ละ step ให้ Cowork อ่านหน้าแบบ interactive เพื่อตรวจ error/required field
- ใช้ screenshot เฉพาะ preview หรือ error ที่ DOM อ่านไม่พอ

ถ้า `entry_mode = AI_ASSISTED`:
- Cowork ใช้ worksheet จาก PHASE 2B มากรอกหลายช่องเป็น batch
- ก่อนกรอก batch ให้สรุปข้อมูลที่จะกรอกและรอ user confirm
- หลังกรอกแต่ละ major step อ่านหน้าแบบ interactive เพื่อตรวจ validation

```
1. เปิด https://admanager.line.biz/
2. Login ด้วย LINE Business ID (user ทำเอง — ห้ามกรอก password ให้)
3. ไปที่ tab "บัญชีผู้ใช้โฆษณา"
4. *** หยุดเช็ค: บัญชีนี้มีบริษัทเดียวกันอยู่แล้วไหม? ***
   → ถ้ามี ให้ user ยืนยันว่าจะสร้างใหม่จริง
5. คลิก "+ บัญชีผู้ใช้โฆษณาใหม่"

- ถ้า `SELF_FILL` ให้ user เป็นคนกรอกค่าตามรายการด้านล่าง และ Cowork ช่วยนำทาง/ตรวจ error
- ถ้า `AI_ASSISTED` ให้ Cowork กรอกค่าจาก worksheet เป็น batch หลัง user confirm

=== Step 1: ข้อมูลสำหรับการเรียกเก็บเงิน ===
6. เลือก "ลูกค้า" = LINE Thailand (default)
7. เลือก "ประเภทธุรกิจ" ตาม Account Type [A/B/C]
8. กรอก Tax ID (จาก [A1]/[B1]/[C1])
9. กรอก "ชื่อบริษัทผู้ชำระเงิน" (จาก [A2]/[B3]/[C2])
10. กรอกรหัสไปรษณีย์ จาก [1]
11. กรอกที่อยู่บริษัท จาก [1]
12. ข้ามชื่ออาคาร (optional)
13. กรอกเบอร์โทรหลัก จาก [2] (ตัด 0 ตัวหน้า เช่น 0850992551 → 850992551)
14. กรอกชื่อผู้ติดต่อ จาก [3]
15. กรอกฝ่ายงาน จาก [4]
16. ถ้า [6] = ใช่ → ติ๊ก checkbox "เหมือนกับหมายเลขโทรศัพท์หลัก"
    ถ้า [6] = ไม่ → กรอกเบอร์ผู้ติดต่ออีกตัว
17. กรอกอีเมล จาก [5]
18. ⚠️ กรอก "ชื่อผู้ชำระเงิน" จาก [12]
    *** สำคัญ: UI label ว่า "ออปชัน" แต่ระบบ validate เป็น required
        ถ้าข้าม จะกด "สร้าง" ไม่ผ่าน Step 1 (เห็นเลข "1" แทน ✓) ***
19. การขอใบกำกับภาษี: ตาม [A3] (default: เต็มรูป)

=== Step 2: ข้อมูลผู้ลงโฆษณา ===
21. กรอกชื่อผู้ลงโฆษณา จาก [7]

23. คลิก "เลือกหมวดหมู่" → modal popup

29. อัปโหลดเอกสาร: เฉพาะกลุ่ม B (ไฟล์ JPG/JPEG/PNG/PDF, ≤5 ไฟล์, ≤10MB/ไฟล์)

=== Step 4: ข้อมูลทั่วไป ===
30. ชื่อบัญชีผู้ใช้โฆษณา: ระบบ auto-fill เป็น "[ชื่อ Advertiser] - [หมวดหมู่]"
    → user ปรับได้ถ้าต้องการ
31. ประเทศเป้าหมาย: ไทย (default — เปลี่ยนไม่ได้หลัง submit) ⚠️
32. เขตเวลา: GMT+7 กรุงเทพ (default — เปลี่ยนไม่ได้) ⚠️
33. สกุลเงิน: THB (default — เปลี่ยนไม่ได้) ⚠️
34. ถ้ามี Promo Code [13] → คลิก "ตั้งค่าอย่างละเอียด" → กรอก

=== Confirm + Submit ===
35. *** หยุด → แสดง Preview ทั้ง 4 Steps → รอ user ยืนยัน ***
36. กดปุ่ม "สร้าง"
37. ระบบ navigate ไปหน้า Payment

=== Payment ===
38. แสดงตัวเลือกวิธีชำระ:
    - LINE Pay (บัตรเครดิต/เดบิต)
    - บัตรเครดิต/เดบิต (ตรง)
39. แจ้ง user: "เลือกวิธีและกรอกข้อมูลบัตรเองครับ"
```

⚠️ **ห้ามกรอกข้อมูลบัตรเครดิต/เดบิต** ไม่ว่ากรณีใด

## PHASE 4 — VERIFY + TROUBLESHOOT

**สำเร็จ:**
> "เยี่ยมเลยครับ! บัญชี ID: [A_xxxxxxxxxxxx] สร้างเรียบร้อย
> LINE จะใช้เวลาพิจารณาไม่เกิน 48 ชั่วโมง
> เมื่อได้รับ Email อนุมัติแล้ว เราพร้อมสร้าง Campaign แรกได้เลยครับ"

**Common Errors:**

| ปัญหา | วิธีแก้ |
|---|---|
| กดสร้างแล้วหน้าไม่ไปไหน Step 1 ยังเป็น "1" | เช็คฟิลด์ **"ชื่อผู้ชำระเงิน" (payerName)** — UI ว่า optional แต่ system validate เป็น required ต้องกรอก |
| OA ID verify ไม่ผ่าน | ตรวจ @ID ที่ manager.line.biz ว่าตรงไหม + status active |
| ชื่อบริษัทไม่ตรง (กลุ่ม B reject) | ต้องตรงเป๊ะกับหนังสือรับรองบริษัท |
| URL invalid | ต้องเป็น https:// + เข้าถึงได้จริง (ไม่ใช่ 404 / down) |
| เอกสารไม่ครบ (กลุ่ม B) | แจ้ง checklist ที่ยังขาดตามประเภทธุรกิจ |
| Tax ID 13 หลักผิด | นิติบุคคลใช้เลขทะเบียนนิติบุคคล / บุคคลธรรมดาใช้เลขบัตรประชาชน |
| เบอร์โทรกรอกไม่ได้ | ตัดเลข 0 ตัวแรกออก (รหัส +66 จะใส่อัตโนมัติ) |
| อื่นๆ | https://lineforbusiness.com/th/contact |

## PHASE 5 — MCP HANDOFF

หลังบัญชีสร้าง/อนุมัติแล้ว และ user ได้สิทธิ์ API:

1. ให้ user นำค่าเหล่านี้มาใส่ `.env` เอง
   - `LINE_ADS_ACCESS_KEY`
   - `LINE_ADS_SECRET_KEY`
   - `LINE_ADS_AD_ACCOUNT_ID`
2. ห้าม hardcode หรือแสดง secret ในแชท
3. รัน read-only smoke test ด้วย MCP:
   - `list_campaigns`
   - `list_audiences`
   - `get_daily_report` หรือ `get_report`
4. ถ้า read-only ผ่าน ให้ switch workflow ถัดไป:
   - Campaign creation → `02-campaign.md`
   - Report → `03-report-schedule.md`
   - Optimize → `04-optimize.md`

ถ้ายังไม่ได้ Access Key/Secret:
- ใช้ Browser ช่วยนำทางไปหน้า API management ได้
- แต่ user ต้องเป็นคนคัดลอก/จัดการ secret เอง
